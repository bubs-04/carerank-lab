# Cloud reference: approval required before provisioning

Nothing in this directory has deployed AWS resources. `platform.yaml` is a minimal CloudFormation reference; `compose.production.yaml` is standalone and never uses lab seeds/default accounts. Local static validation is not proof of AWS runtime compatibility.

## Controls and prerequisites

- An existing same-region ACM certificate and approved DNS hostname; HTTPS ALB with HTTP redirect and TLS 1.2/1.3. Host port 8080 accepts only the ALB security group. RDS is private, encrypted, deletion-protected, forces TLS and retains seven days of backups. Replacement/deletion snapshots preserve data.
- SSM-managed host, no SSH ingress, encrypted EBS, IMDSv2 with hop limit 1. Nginx trusts only the two ALB subnets, selects the last ALB-appended client address, overwrites the application client-IP header and clears arbitrary forwarding headers. API trusts only the fixed proxy address.
- Separate owner/API/worker secrets. Runtime files are UID 1000 mode 0400 under root-only 0700 directories. API/worker containers run without root, capabilities or writable root filesystems. Nginx access logs are disabled; application logs are sanitized JSON in CloudWatch, retained 30 days.
- Existing private ECR repositories, reviewed digest-pinned images and an installed, version-pinned Docker Compose v2 CLI are prerequisites. UserData installs Docker only; no migrations, accounts or app deployment occurs on infrastructure creation. Verify package installation and ECR access in the approved AWS environment.
- Configure GitHub environment `production-review` with required human reviewers, prevent self-review and restrict deployment branches to `main`. The manual release workflow verifies exact commit CI and writes a receipt; it has no AWS credentials or deployment step. Without those repository protections, the receipt alone is **not** a human approval. Review image provenance and signatures separately; this project does not prove that supplied ECR digests were built from the receipt commit.

## Operator sequence (after explicit approval)

1. Validate locally: `cfn-lint infra/platform.yaml`; review the CloudFormation change set, region, certificate and cost. Only then create resources. No AWS command was executed during development.
2. Obtain immutable backend/web images from the reviewed source. Install the Docker Compose plugin from a verified release, authenticate to approved ECR, and restrict who can start SSM/root sessions.
3. Download the official [RDS CA bundle](https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem) over verified HTTPS, review its certificate chain/checksum and mount it read-only. URLs require `sslmode=verify-full`; do not turn certificate validation off.
4. Copy `release.env.example` to an operator-owned private path. Fill exact Git SHA, ECR digests, public origin, private host address, log group, CA path/checksum and release identity. No passwords belong in this manifest.
5. Run `fetch_secrets.py` as the approved root operator with the three exact stack output ARNs, RDS hostname and region. It retrieves only those secrets and atomically writes private URL files. RDS-generated owner passwords may be 28 characters; API/worker passwords are independently generated at 48 characters.
6. Take/verify a backup before migration. Run `check_release.py MANIFEST`, then `deploy.py MANIFEST reviewed-release.json --approved-change CHANGE-REFERENCE`. Migration and grants precede runtime replacement. The helper stops workers, recreates API/worker/proxy, checks API and worker readiness and removes the owner URL file afterward. It does not seed or downgrade data. Retrieve the owner secret again for a later operator change.
7. Validate ALB HTTPS/cookies/CSRF, login roles, queue recovery, logs and backup alarms. Production account onboarding/SSO is intentionally not implemented: development-only provisioning must not be exposed as a public registration route. Securely establish a separately reviewed production identity process before public operation.

## Backup and rollback

RDS automated backups provide configured retention, not a measured RPO/RTO. Schedule and observe restore drills to a new isolated instance; compare counts/fingerprints and provision new runtime roles. Encrypt and restrict logical dumps, which contain password hashes/session history. Never restore over a retained production database. `scripts/verify_reliability.py` demonstrates the method on local disposable PostgreSQL only; it does not test RDS failover.

For application rollback, stop the worker, retrieve the prior approved digest manifest from `/var/lib/carerank/releases`, and check compatibility with the current schema before replacing images. Keep the additive migration; do not run Alembic downgrade on retained data. A failed migration/readiness gate leaves the worker stopped or deployment incomplete for inspection; there is no unsafe automatic database rollback. A host reboot loses `/run` secrets: an approved operator must retrieve them before restoring containers. Automate this through a separately reviewed narrow-privilege bootstrap before claiming unattended recovery.

## Limits, threats and cost

This is not a production-ready service: no real AWS deployment/TLS/RDS privilege test, multi-host failover, SSO/MFA/password-reset workflow, tamper-proof external audit archive, secret rotation drill or paging integration has been verified. A compromised host/root/instance profile can retrieve all three secrets, including the migration owner; container separation is not host isolation. Restrict SSM/IAM and consider a separate migration identity/host before sensitive use. The runtime role has table privileges, not per-tenant RLS; this is a single workspace. The public host has HTTPS egress for ECR/SSM/CMS, not a destination allowlist. ALB→host traffic is HTTP inside the VPC; end-to-end TLS remains an additional requirement for a stricter threat model. No PHI or clinical use is authorized.

Planning allowance for us-east-1, 730 hours/month, one t3.small host, db.t4g.small single-AZ RDS, 20GB EBS + 20GB RDS, one low-traffic ALB, public IPv4, three secrets and light logs: **roughly $100–160/month**, before taxes, substantial egress/LCUs/logs/backups, larger storage or CPU-credit charges. Multi-AZ RDS and larger hosts cost more. These are unverified budgeting ranges, not a current price quote. Recalculate with [AWS Pricing Calculator](https://calculator.aws/) and [EC2](https://aws.amazon.com/ec2/pricing/), [RDS](https://aws.amazon.com/rds/postgresql/pricing/), [ALB](https://aws.amazon.com/elasticloadbalancing/pricing/) pricing before approval. Set budgets/alerts explicitly; no paid resources were launched here.
